# 已知限制

本頁只描述目前程式已確認的邊界，不把部分驗證寫成完整相容保證。

## 1. 大型文字輸入

- `128000` 個 UTF-16 碼元是預設的 Web 相容政策；超過此設定的呼叫端文字會由 Sidecar 拒絕。
- Microsoft 後端可能接受更大的直接輸入，但處理時間與成功率沒有穩定保證。
- 「後端接受請求」不等於「能在合理時間內完成」。

## 2. 大型工具結果

- 大型工具結果仍有被上游壓縮或截短的風險。
- 若呼叫端要求逐位元組保留大型工具輸出，必須先以實際負載驗證，不應只依賴一般文字與小型工具測試。

## 3. 同一輪的多個呼叫端工具

- 呼叫端通常可以解析多筆 `tool_calls`，但 Sidecar 尚未對同一個 assistant turn 產生多個獨立呼叫端工具提供完整端對端保證。
- 需要 `parallel_tool_calls` 時，應先針對目標模型與呼叫端進行實測。

## 4. Bing 與呼叫端工具混用

- 原生 Bing 並非必然與呼叫端工具衝突。
- 實際路由高度依賴工具提示詞；過度限制的文字可能讓模型只選呼叫端工具而不使用 Bing。
- 發生衝突時應先檢查提示詞契約，不要先移除 Bing 或另造搜尋工具。

## 5. Code Interpreter 產出檔案

- Sidecar 已實作帶認證的上游擷取與產出檔案物化，不會把瀏覽器 `blob:` URL 或受保護的 Microsoft 暫時網址直接交給呼叫端。
- 成功擷取後，檔案會存入本機私有儲存區並回傳短期下載網址（capability URL）；網址的持有者即可下載，預設有效期為 24 小時，因此必須視同短期憑證保護。
- 遠端提供下載連結時必須設定正確的 `M365_PUBLIC_ORIGIN`，且 loopback 以外只接受 HTTPS。
- 若上游認證、檔案完整性或本機容量檢查失敗，物化流程會失敗關閉，不會退回受保護的上游網址。

## 6. Private 模式的隱私邊界

- `disableMemory=1` 可避免一般聊天歷史，但不代表 Microsoft 完全不保留資料。
- 文件與圖片走不同的傳輸路徑；一般文件仍可能在 OneDrive 或 SharePoint 建立暫存副本。
- 對外說明不應把 Private 模式簡化成「零保留」。

## 7. MCP 可用性

- `/v1/mcp`、`/v1/mcp/sse` 與 `/v1/mcp/message` 均已掛載，並要求有效的 Bearer API 金鑰。
- `/v1/mcp` 使用 Streamable HTTP；後兩者是成對的舊版 SSE 傳輸。呼叫端必須支援所選傳輸與 MCP 初始化流程。
- 目前內建 provider 只提供 `wp6_echo` 互通驗證工具；這些路由不是任意外部 MCP server 的自動登錄中心。

## 8. 上游關係

- 公開 `gpxsrz/M365-Copilot2API` 的 `main` 是本專案唯一開發主線。
- `HEXUXIU/M365-Copilot2API` 僅供唯讀比較，不承諾自動同步或功能完全一致。
- 若要匯入上游變更，必須先逐項檢查差異與本專案測試，再透過公開主線整合。

## 9. 容器首次啟動

- `Dockerfile` 可建置非 root 容器映像，但一般 bridge/NAT 不會讓容器內收到真正的 loopback 管理請求。
- 一次性 bootstrap secret 在非 loopback 管理介面會被安全策略拒絕，因此本專案不提供未經驗證的通用 Compose 快速啟動。
- 容器部署必須自行處理 HTTPS、可信反向代理、資料卷擁有權與持久管理員密碼；不得以放寬管理介面安全檢查作為捷徑。
