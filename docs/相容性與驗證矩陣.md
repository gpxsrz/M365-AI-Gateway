# 相容性與驗證矩陣

下表只保留公開安全、對實作者有用的結論；`已驗證` 代表對應行為已有實測或程式契約支持，`部分驗證` 代表只證明了部分路徑，`待補強` 代表公開快照仍保留明確缺口。

| 類別 | 項目 | 狀態 | 說明 |
| --- | --- | --- | --- |
| API | `POST /v1/chat/completions` | 已驗證 | 主要相容端點，支援一般文字與 SSE streaming。 |
| API | `POST /v1/responses` | 部分驗證 | 保留相容層，但主要 consumer 驗證仍集中在 `/v1/chat/completions`。 |
| API | `POST /v1/messages` | 部分驗證 | 保留 Anthropic 形狀相容層。 |
| Streaming | SSE delta + terminal + `[DONE]` | 已驗證 | partial event 與 terminal completion 可映射到標準 SSE 結尾。 |
| 文字政策 | `128000` UTF-16 Web compatibility | 已驗證 | 適合作為預設產品政策，不應描述成 backend hard limit。 |
| Conversation | strict hash-prefix checkpoint reuse | 已驗證 | 建議只在 prefix 完全一致時重用 upstream conversation。 |
| Private mode | `disableMemory=1` per connection | 已驗證 | 每條新 ChatHub WebSocket 都應重套。 |
| Private mode | no ordinary chat history outcome | 已驗證 | `disableMemory=1` 對 no-history outcome 有直接實效。 |
| Memory boundary | 長期 memory 由 consumer 管理 | 已驗證 | Sidecar 只保留短期 transport continuation state。 |
| Files | 一般文件 grounding | 已驗證 | 文件先取得 Microsoft file identity，再經 ChatHub annotation 引用。 |
| Files | 3 個 active attachments | 已驗證 | 文件與圖片共用同一 turn 的 active quota。 |
| Files | OneDrive / SharePoint staging side effect | 已驗證 | no-history 不等於沒有 staging copy。 |
| Vision | 單圖 / 多圖理解 | 已驗證 | 圖片會真正進入模型處理。 |
| Vision | 圖片與文件分流 transport | 已驗證 | 不應把兩條上游路徑硬合成一套。 |
| Built-in tools | Bing Web Search 單獨使用 | 已驗證 | citations / grounding 可出現。 |
| Built-in tools | Bing + `Code Interpreter` 同 turn | 已驗證 | 兩者可共存。 |
| Caller tools | 單一 caller tool continuation | 已驗證 | 基本 `tool_calls` / `tool_call_id` 路徑可成立。 |
| Caller tools | native Bing + caller tool coexistence | 部分驗證 | 能否共存高度依賴 tool-routing prompt wording。 |
| Caller tools | 同一 assistant turn 多個 caller tools | 待補強 | consumer 可吃多 call，但 Sidecar 端仍有明確缺口。 |
| Tool results | 大型 tool result 完整保留 | 待補強 | 現有快照仍有 result flatten / truncation 風險。 |
| Code Interpreter | Python execution | 已驗證 | 上游可實際執行程式並回傳結果。 |
| Code Interpreter | output-file metadata | 已驗證 | 上游會產生正式 output-file reference。 |
| Code Interpreter | 對外可下載 artifact 回傳 | 待補強 | 仍需 Sidecar 補完 authenticated artifact fetch。 |
| MCP | modern handler | 已驗證 | 程式樹內有 modern MCP 實作。 |
| MCP | legacy SSE handler | 已驗證 | 程式樹內保留 legacy handler。 |
| MCP | consumer 直接互通 | 待補強 | 是否可用仍取決於實際路由掛載與 consumer 路徑。 |
| Hermes 類 consumer | core custom provider via `/v1/chat/completions` | 已驗證 | 文字、streaming、單一 tool、Vision 與 continuation 已有正向證據。 |
| Hermes 類 consumer | Files API direct exercise | 未主張 | 既有 consumer 驗證重點不在 direct file object path。 |
