# 相容性與驗證矩陣

下表只保留公開安全、對實作者有用的結論；`已驗證` 代表對應行為已有實測或程式契約支持，`部分驗證` 代表只證明了部分路徑，`待補強` 代表目前實作仍保留明確缺口。

| 類別 | 項目 | 狀態 | 說明 |
| --- | --- | --- | --- |
| API | `POST /v1/chat/completions` | 已驗證 | 主要相容端點，支援一般文字與 SSE streaming。 |
| API | `POST /v1/responses` | 部分驗證 | 保留相容層，但主要 consumer 驗證仍集中在 `/v1/chat/completions`。 |
| API | `POST /v1/messages` | 部分驗證 | 保留 Anthropic 形狀相容層。 |
| Streaming | SSE delta + terminal + `[DONE]` | 已驗證 | partial event 與 terminal completion 可映射到標準 SSE 結尾。 |
| 文字政策 | `128000` UTF-16 Web compatibility | 已驗證 | 適合作為預設產品政策，不應描述成 backend hard limit。 |
| 文字政策 | 一般 `/v1` recovery metadata | Production 已驗證 | #44 已完成 deterministic 與 Production live 驗證：`/v1/chat/completions`、`/v1/responses`、`/v1/messages` 在 128001 UTF-16 時維持 `text_policy_exceeded`，並回 `caller_text_utf16`、`limit=128000`、`received=128001` 與 reduction-and-retry metadata。 |
| 文字政策 | `/memory/v1` overflow recovery | Production 已驗證 | #43 已完成 deterministic 與 Production live 驗證：HTTP 400 `context_length_exceeded` + `input is too long`，同時保留真實 UTF-16 metadata。Hindsight Reflect 最終使用 `max_context_tokens=40000`、Reflect retry `1`：deterministic 400 最多多重送 1 次，同時保留一次 transient ChatHub/502 retry。retry `0` 曾把一次 WebSocket handshake 500→M365 502 直接放大成 reflect 500；改成 1 後臨時 bank retain / recall / reflect 皆成功並完成清理。 |
| Conversation | strict hash-prefix checkpoint reuse | 已驗證 | 建議只在 prefix 完全一致時重用 upstream conversation。 |
| Private mode | `disableMemory=1` per connection | 已驗證 | 每條新 ChatHub WebSocket 都應重套。 |
| Private mode | no ordinary chat history outcome | 已驗證 | `disableMemory=1` 對 no-history outcome 有直接實效。 |
| Memory boundary | 長期 memory 由 consumer 管理 | 已驗證 | Sidecar 只保留短期 transport continuation state。 |
| Files | 一般文件 grounding | 已驗證 | 文件先取得 Microsoft file identity，再經 ChatHub annotation 引用。 |
| Files | 3 個 active attachments | 已驗證 | 文件與圖片共用同一 turn 的 active quota。 |
| Files | OneDrive / SharePoint staging side effect | 已驗證 | no-history 不等於沒有 staging copy。 |
| Vision | 單圖 / 多圖理解 | 已驗證 | 圖片會真正進入模型處理。 |
| Vision | 圖片與文件分流 transport | 已驗證 | 不應把兩條上游路徑硬合成一套。 |
| Built-in tools | Bing Web Search 單獨使用 | 已驗證 | citations / grounding 可出現。 |
| Built-in tools | Bing + `Code Interpreter` 同 turn | 已驗證 | 兩者可共存。 |
| Caller tools | 單一 caller tool continuation | 已驗證 | 基本 `tool_calls` / `tool_call_id` 路徑可成立。 |
| Caller tools | native Bing + caller tool coexistence | 部分驗證 | 能否共存高度依賴 tool-routing prompt wording。 |
| Caller tools | 同一 assistant turn 多個 caller tools | Production 已驗證 | #42 已改為模型生成前固定 ceiling：只有所有可選工具都明確 read-only 才允許 >1，其他情況事前序列化成 1；不再事後降級或截斷。Production 以兩個未帶 `readOnlyHint` 的 Hermes tools 實測第一輪只產生 1 個 `read_file`，第二輪同 session/tool result 正常續接並 `stop`。 |
| Caller tools | model-router 大型 structured arguments | Production + deterministic 已驗證 | #54 移除 repair prompt 的固定 6000 字元截斷，streaming / non-streaming deterministic tests 證明 malformed outer JSON 進入 repair 時完整保留 arguments，repair input 超過 UTF-16 budget 則在第二次 upstream call 前 fail closed。Production Hermes canary 實際執行超過 13K 字元、含中段 sentinel 的 `execute_code` arguments 成功；該 canary 沒有強制進入 repair，因此 live evidence 證明大型 arguments transport，而 repair losslessness 由 deterministic tests 證明。 |
| Caller tools | final-answer router envelope normalization | Production 已驗證 | #57 在共用 OpenAI chat final-answer 邊界修正 internal `calls/answer` envelope 外漏。Generic `/v1`、Hermes `/hermes/v1`、Memory `/memory/v1` 的 streaming / non-streaming 均有 Production live canary；ordinary JSON 保留，non-empty calls、duplicate internal keys、extra fields 或 wrong types fail closed，malformed JSON 不猜測式剝殼。Memory JSON Schema 另有 live 驗證。 |
| Caller tools | 跨 turn 的 tool-round 總量 | 已驗證 | 一個 assistant tool-call turn 算 1 round。一般 `/v1` / Memory 預設 16；Hermes 專用 `/hermes/v1` 預設 128 且可獨立設定。Deterministic handler tests 已涵蓋 Hermes 16→17 continuation、>16 checkpoint/tool identity、generic/Memory 16 terminal、Responses/Anthropic generic policy 與 Hermes 128 runaway terminal。 |
| Tool results | 大型 tool result 完整保留 | 待補強 | 目前實作仍有 result flatten / truncation 風險。 |
| Code Interpreter | Python execution | 已驗證 | 上游可實際執行程式並回傳結果。 |
| Code Interpreter | output-file metadata | 已驗證 | 上游會產生正式 output-file reference。 |
| Code Interpreter | 對外可下載產出檔案 | 已驗證 | Sidecar 會以已登入身分擷取上游檔案、存入本機私有儲存區，再回傳短期下載網址。 |
| MCP | modern handler | 已驗證 | 程式樹內有 modern MCP 實作。 |
| MCP | legacy SSE handler | 已驗證 | 程式樹內保留 legacy handler。 |
| MCP | 呼叫端直接互通 | 部分驗證 | Modern 與舊版 SSE 路由均已掛載；實際相容性仍取決於呼叫端支援的傳輸與初始化流程。 |
| Generic OpenAI consumer / legacy Hermes-like integration | `/v1/chat/completions` | 已驗證 | 文字、streaming、單一 tool、Vision 與 continuation 已有正向證據；正式 Hermes 整合另使用 `/hermes/v1/chat/completions`。 |
| Hermes 類 consumer | Files API direct exercise | 未主張 | 既有 consumer 驗證重點不在 direct file object path。 |
| Hermes | `GET /hermes/v1/models`、`POST /hermes/v1/chat/completions` | Production 已驗證 | 專用 route、獨立 `hermes` checkpoint namespace、#41 overflow recovery、#42 tool ceiling/continuation、#57 final-answer normalization 均有 Production 正向證據。2026-08-12 的 80K/41K 短中型 canary 曾成功；2026-08-13 長任務證據後，現行 Production 基線改為 `context_length=64000`、`proactive_prune_tokens=41000`、`max_attempts=3`、`protect_last_n=20`。 |
| Hindsight | `GET /memory/v1/models`、`POST /memory/v1/chat/completions` | 核心 Production 已驗證 | Retain／recall／reflect、`/memory/v1` overflow recovery、40K/retry-1、#57 stream/non-stream final-answer 與 JSON Schema 均有 live evidence。FIFO、429 cooldown、fact-preserving repair guard 由 deterministic tests 驗證；真實 Microsoft 帳號刻意不以高併發強制觸發 429。自動注入為 observation-only / 2048 tokens；Hermes upstream #18774 修復前，bank mission 以 Hindsight Banks Config API 直接 PATCH `reflect_mission` / `retain_mission` 並以 GET 讀回。 |
| Compatibility traffic | 互動流量優先 / Memory admission control | 部分驗證 | `/v1/chat/completions` 與 `/hermes/v1/*` 會阻擋新 Memory 入場；Memory concurrency、FIFO queue、holdoff 與 429 cooldown 以本地 deterministic test 驗證，不以高併發實機強制觸發 429。2026-08-13 runtime readback 為 concurrency 1、queue 60s、interactive holdoff 300s、backoff 30→600s；已在執行的 Memory 不會被搶占。 |

# Compatibility and Validation Matrix

`Verified` means the behavior has direct test evidence or an enforced code contract. `Partially verified` means only part of the path is proven. `Needs work` marks a known implementation gap.

| Category | Item | Status | Notes |
| --- | --- | --- | --- |
| API | `POST /v1/chat/completions` | Verified | Primary general compatibility endpoint with text and SSE streaming. |
| API | `POST /v1/responses` | Partially verified | Compatibility layer remains available, but primary consumer validation centers on `/v1/chat/completions`. |
| API | `POST /v1/messages` | Partially verified | Anthropic-shaped compatibility layer remains available. |
| Streaming | SSE delta + terminal + `[DONE]` | Verified | Partial events and terminal completion map to a standard SSE ending. |
| Text policy | `128000` UTF-16 web compatibility | Verified | Product policy, not a claimed backend hard limit. |
| Text policy | generic `/v1` recovery metadata | Production verified | #44 passed deterministic and Production live verification: `/v1/chat/completions`, `/v1/responses`, and `/v1/messages` keep `text_policy_exceeded` at 128001 UTF-16 while returning `caller_text_utf16`, `limit=128000`, `received=128001`, and reduction-and-retry metadata. |
| Text policy | `/memory/v1` overflow recovery | Production verified | #43 passed deterministic and Production live verification: HTTP 400 `context_length_exceeded` plus `input is too long`, with the real UTF-16 metadata preserved. The final Hindsight Reflect settings are `max_context_tokens=40000` and retry `1`: deterministic 400s are repeated at most once while one transient ChatHub/502 retry remains available. A retry-`0` canary turned a single WebSocket handshake 500 → M365 502 into an immediate reflect 500; after switching to 1, a temporary bank completed retain / recall / reflect and was cleaned up. |
| Conversation | strict hash-prefix checkpoint reuse | Verified | Upstream conversations are reused only when the history prefix matches exactly. |
| Private mode | `disableMemory=1` per connection | Verified | Reapplied for each new ChatHub WebSocket. |

| Vision | single/multiple image understanding | Verified | Images are actually processed by the model. |
| Built-in tools | Bing Web Search | Verified | Citations and grounding can be produced. |
